## 模型与 Skill 对照

本轮使用 Spark 上 `qwen3.6:35b-a3b` 做十组固定题目，无 Skill / 有 Skill 各回答一次。
模型无执行工具，仅检查说明和边界，不声称完成真实构建。原始回答保留于
`prompt-initial.json`，修订后复测于 `prompt-retest.json`。

- Asset：有 Skill 时正确提出模板、主色、缩放与 manifest 检查；不接管重力。
- Personality：正确拒绝从儿童绘画推断情绪。首轮把输出目录说成需已存在，修订后纠正。
- Scene：保留表情和来源，拒绝把缺贴图静默替换成纯色再报成功。
- Optimizer：首轮未清晰提出默认审计；修订后明确 `preserve` 无视觉降级且无实测 GPU 收益，`preview` 需接受画质取舍。
- Runner：首轮正确拒绝仅凭退出码 0 宣称成功，但在 6kg / 11N 地球题里漏掉推力不足说明。已在 Skill 增加 `F > mg` 判断说明；复测时服务报 CUDA 非法内存访问，尚不能把修订效果记为通过。

保留缺陷、修订及服务失败，不汇总成虚假的 100% 成功率。Personality 的简短复测
仍未逐项复述全部默认/手动约束，因此也不把两条短回答当成完整行为验收。
首轮无 Skill 有把归档小误说成显存收益、仅凭退出码答应通过等问题；
小样本提示词对照不能证明广泛效果提升。

Qwen3.6 先前通过的 Agent 集成记录仍保留；追加评测暴露运行时不稳定，
见 `runner-service-error.json`。不改用 mock 掩盖错误。演示配置继续用已验证的
Qwen2.5 网页路线。21:43（北京时间）仅卸载本轮 Qwen3.6 GPU 实例后，
Qwen2.5 短请求实际返回 `OK`，未删除权重或重启服务；该健康检查不是重新进行全流程验收。

负责人随后明确要求优先提交当前开发版，暂停追加验收。源码可以发布，但不标成
完整 Verified，不将未执行的冻结包签名或模型网页验收记为通过。

### 提交前追加记录

Qwen3.6 完成前四个 Skill 的 24 道说明题后，Runner 题再次出现 CUDA 错误；
冷启动仍复现。改为相同权重、`num_batch=128` 后，Runner 六道题均正常返回。
其中 6kg / 11N 地球题正确给出 58.86N 重量及推力不足判断；退出码与人工键盘
测试边界题也符合要求。Personality 的默认自然、手动生气及目录约束题已补充复核。
另发现不应建议结束非本人进程、故事重力不可修改、Scene ID / 输出目录说明等
问题，已收紧 Skill 说明；这些最后修订尚未完成全量复测。

因此本次发布状态为开发预览：已有真实集成与双端回归证据，完整行为验收仍部分
待完成。原始模型错误未删除。Qwen3.6 为目标模型，Qwen2.5 是历史验收记录。

## 扫描处理

Bandit 原始结果：4,143 行，0 高、8 中、22 低，0 扫描错误，未用 `nosec` 隐藏结果。
8 个中等级均位于测试代码：5 个是故意提交的非法路径，2 个是本机 HTTP 测试，
1 个是在断言中确认禁止绑定 `0.0.0.0`。22 个低等级包括测试假 token、subprocess
导入及执行。生产路径的 4 个提示为 Agent 和 Runner 各一次导入/执行：固定 argv、
不启用 shell、解释器由受信操作者配置、只管理自身进程组。
原始报告见 `bandit.json`；这些是人工接受的本地单用户风险，不等于没有风险。
